# Surtr REPL 単体仕様書

## 1. 目的

Surtr REPL は、単なる対話実行環境ではなく、以下を一体で扱うための TUI ベース実行環境とする。

- 式・定義の入力
- 評価結果の履歴参照
- 過去入力の再利用
- シンボルのドキュメント参照
- コマンドによる内省操作
- 補完による入力支援

本仕様は、VMViewer を含まない REPL 単体モードを対象とする。

## 2. 設計方針

### 2.1 基本方針

- REPL は 1画面完結の TUI とする
- 画面はペイン構成を持つ
- 入力は通常入力モードとコマンドモードを持つ
- コマンドはグローバルとペイン専用に分かれる
- 補完は現在の入力文脈とフォーカス中ペインに応じて出し分ける
- 履歴は CLI 的に時系列表示する
- ドキュメント表示はキュー方式で管理する

### 2.2 想定利用

- 言語機能の試行
- 標準ライブラリ探索
- 型やシグネチャ確認
- コンパイラ内部表示系コマンドへの拡張
- 過去結果を参照しながらの反復実験

## 3. 画面構成

### 3.1 ペイン一覧

REPL 画面は以下のペインで構成する。

1. 実行結果ペイン
2. ドキュメントビューペイン
3. 補完ペイン
4. 入力ペイン
5. ステータスバー

### 3.2 レイアウト

基本レイアウトは以下とする。

```text
+-------------------------------------------------------------+
| Results / History                                           |
|                                                             |
|                                                             |
|-------------------------------------------------------------|
| Docs Queue                                                  |
|                                                             |
|-------------------------------------------------------------|
| Completion                                                  |
|                                                             |
|-------------------------------------------------------------|
| > input area                                                |
|   multiline input...                                        |
|-------------------------------------------------------------|
| MODE | Focus | Help | Status                                |
+-------------------------------------------------------------+
```

#### 3.2.1 実行結果ペイン

- 画面上部の主領域
- 実行結果、エラー、コマンド出力を時系列で表示
- CLI の履歴表示に近い見た目とする
- 入力ペインの伸長に応じて、残りの高さを使用する

#### 3.2.2 ドキュメントビューペイン

- 実行結果ペインの下に配置
- シンボルのドキュメント参照結果をキュー方式で表示
- 複数件を保持可能
- フォーカス・削除・クリア対象になる

#### 3.2.3 補完ペイン

- 入力ペインの直上に配置
- 現在入力中のトークンや `:` コマンドに応じて候補を表示
- 候補がない場合は非表示または最小高さ表示

#### 3.2.4 入力ペイン

- 画面下部に固定
- 複数行入力に対応
- 行数に応じて縦方向へ伸長する
- 通常入力とコマンドモードの両方の起点になる

#### 3.2.5 ステータスバー

- 最下部 1 行固定
- 現在モード、フォーカス、簡易ヘルプ、状態を表示する

## 4. ペイン仕様

### 4.1 実行結果ペイン

#### 4.1.1 役割

- 評価結果の表示
- エラー表示
- REPL コマンドの出力表示
- スクロール参照
- 履歴位置へのジャンプ

#### 4.1.2 表示対象

表示エントリは少なくとも以下を含む。

- 入力コード
- 評価結果
- エラー
- 情報メッセージ
- コマンド出力

#### 4.1.3 エントリ構造

各エントリは次のメタ情報を持つ。

- `idx`
- 種別
- 元入力
- 表示本文
- 成功/失敗状態
- 必要に応じて時刻や実行時間

種別例:

- `Input`
- `Result`
- `Error`
- `Info`
- `CommandOutput`

#### 4.1.4 操作

フォーカス中は以下を行える。

- 上下でスクロール
- `:j idx` で指定行付近へジャンプ
- 将来的に pin や copy へ拡張可能

### 4.2 ドキュメントビューペイン

#### 4.2.1 役割

- シンボルの説明参照
- シグネチャ確認
- コード断片確認
- 複数ドキュメントの保持

#### 4.2.2 表示内容

1件のドキュメント表示は次を基本とする。

- シンボル名
- 種別
- シグネチャ
- 短い説明
- 所属モジュールまたは impl
- 必要に応じてソース断片

#### 4.2.3 管理方式

- キュー方式
- 新規参照は末尾追加
- `idx` によりフォーカス可能
- 個別削除、全削除が可能

#### 4.2.4 追加方法

グローバルコマンドから追加する。

例:

- `:doc List::map`
- `:sig List::map`

### 4.3 補完ペイン

#### 4.3.1 役割

- 入力支援
- コマンド候補提示
- シンボルの種別と型情報の提示

#### 4.3.2 配置

- 入力ペインの直上

#### 4.3.3 更新契機

以下で更新する。

- 文字入力
- 削除
- カーソル移動
- `:` 入力によるコマンドモード遷移
- 入力ペイン再フォーカス時

#### 4.3.4 表示件数

- 初期実装では固定件数 5〜8 件程度
- 件数超過時は内部選択状態のみ移動、表示スクロール対応可

#### 4.3.5 候補表示内容

各候補は以下を持つ。

- ラベル
- 種別
- 型またはシグネチャ
- 必要に応じて短い説明

表示例:

```text
num        local  Int
nums       local  List<Int>
map        fn     (List<A>, A -> B) -> List<B>
Result     type   Result<T, E>
doc        cmd    show docs for symbol
```

#### 4.3.6 文脈別補完

通常入力中:

- ローカル変数
- 関数
- モジュール
- 型
- キーワード

`:` 直後:

- コマンド補完

`Module::` 後:

- そのモジュール配下候補

### 4.4 入力ペイン

#### 4.4.1 役割

- 式・定義の入力
- コマンドの入力
- 履歴再利用結果の編集

#### 4.4.2 伸長仕様

- 入力行数に応じて縦方向へ伸長する
- 最大高さは画面全体とのバランスで制限可能
- 制限超過時は内部スクロール

#### 4.4.3 モード

入力ペインは以下の状態を持つ。

- `Insert`
- `Command`

Insert は通常コード入力状態、Command は `:` 起点のコマンド入力状態とする。

#### 4.4.4 `:` の挙動

- 行頭 1 文字目に `:` を入力した場合、コマンドモードへ移行
- コマンドモード中に再度 `:` を押した場合、通常入力へ戻る

#### 4.4.5 キー操作

共通:

- 左右: カーソル移動
- 上下: 補完候補選択または入力履歴系挙動
- `Ctrl+C`: 終了

Insert モード:

- 文字入力
- 改行
- 補完候補選択
- 実行

Command モード:

- コマンド文字列編集
- コマンド補完
- コマンド実行

#### 4.4.6 履歴再利用

以下をサポートする。

- `:v idx`
  - 実行結果 N 番目の入力を入力エリアへコピー

このとき、コピー先は編集可能な入力バッファとする。

### 4.5 ステータスバー

#### 4.5.1 役割

- 現在状態の可視化
- 最低限の操作ヘルプ提示

#### 4.5.2 表示内容

最低限以下を含む。

- 入力モード
- フォーカス中ペイン
- 補完状態
- キーガイド
- 簡易ステータス

表示例:

```text
INSERT | Focus: Input | Enter Run | : Command | Tab Focus | Ctrl-C Quit
```

## 5. フォーカスモデル

### 5.1 フォーカス対象

フォーカス対象は以下とする。

- Input
- Results
- Docs

補完ペインは独立フォーカスを持たず、入力ペインの補助表示とする。

### 5.2 フォーカス切替

- `Tab` または別途定義したキーで次ペインへ移動
- `Shift+Tab` で前ペインへ移動可能としてよい
- フォーカス中ペインは視覚的に明示する

### 5.3 視覚表現

少なくとも以下のいずれかで明示する。

- 枠線強調
- タイトル強調
- 先頭マーカー表示

## 6. コマンド体系

### 6.1 分類

コマンドは次の2種に分ける。

- グローバルコマンド
- ペイン専用コマンド

### 6.2 グローバルコマンド

すべてのペインで共通に利用可能。

初期実装では以下を基本とする。

- `:q`
- `:help`
- `:doc <symbol>`
- `:sig <symbol>`
- `:type <expr>`

意味:

- `:q`: REPL を終了する
- `:help`: コマンド一覧や簡易説明を表示する
- `:doc <symbol>`: 指定シンボルのドキュメントをドキュメントビューへ追加する。シグネチャは先頭に必ず表示する
- `:sig <symbol>`: 指定シンボルのシグネチャのみを表示する。表示先は結果ペインまたはドキュメントビューの簡易表示とする
- `:type <expr>`: 式の型を表示する

### 6.3 ペイン専用コマンド

Input ペイン:

- `:v idx`
  - 指定履歴の入力内容を入力エリアへコピー

Results ペイン:

- `:j idx`
  - 指定行付近を中心に表示する

Docs ペイン:

- `:doc-focus idx`
  - 指定ドキュメントへフォーカス
- `:doc-drop idx`
  - 指定ドキュメントを削除
- `:doc-clear`
  - 全ドキュメントを削除

### 6.4 コマンド命名方針

- グローバルは短く一般的な名前
- ペイン専用は衝突を避けるため、必要に応じて接頭辞を付与
- `type` は式用、`sig` は定義シグネチャ用として意味を分離する

## 7. 補完仕様

### 7.1 補完対象

通常入力:

- ローカル変数
- 関数
- モジュール
- 型
- キーワード

コマンド入力:

- グローバルコマンド
- フォーカス中ペイン専用コマンド

### 7.2 補完候補の生成

補完候補は次をマージして得る。

- グローバル候補
- ペイン専用候補
- 現在の構文文脈に合うシンボル候補

### 7.3 候補表示順

推奨優先順位:

1. 完全一致に近いもの
2. prefix 一致
3. ローカル変数
4. 関数
5. モジュール
6. 型
7. キーワード
8. 補助的候補

### 7.4 選択挙動

- 上下で候補選択
- `Enter` または `Tab` で確定可能
- 確定後、入力バッファへ反映

## 8. 入力と実行

### 8.1 実行単位

入力ペインの内容を 1 単位として評価する。

初期実装では以下のいずれかを採用する。

- `Enter` で単行入力を実行、複数行時は別キーで確定
- または専用確定規則を持つ

ここは文法仕様との整合に応じて別途決める。

### 8.2 実行結果の記録

実行後、以下を履歴へ追加する。

- 入力内容
- 成功時の結果
- 失敗時のエラー

### 8.3 実行後の入力欄

初期実装では以下のどちらかでよい。

- クリアする
- 残す

ただし内部的には、未送信入力と再利用入力を分けられる構造が望ましい。

## 9. データモデル

以下のような状態モデルを想定する。

```rust
enum FocusPane {
    Input,
    Results,
    Docs,
}

enum InputMode {
    Insert,
    Command,
}

enum PaneKind {
    Input,
    Results,
    Docs,
}

struct ReplApp {
    focus: FocusPane,
    input_mode: InputMode,
    input_buffer: String,
    command_buffer: String,
    results: Vec<ReplEntry>,
    docs_queue: Vec<DocEntry>,
    selected_result: Option<usize>,
    selected_doc: Option<usize>,
    completion: CompletionState,
    status: StatusLine,
}
```

## 10. コマンド表現モデル

コマンドは補完・表示用メタデータと、実行用表現を分離する。

実行用:

```rust
enum GlobalCommand {
    Quit,
    Help,
    Doc { symbol: String },
    Sig { symbol: String },
    TypeOf { expr: String },
}

enum InputPaneCommand {
    ViewResult { idx: usize },
}

enum ResultPaneCommand {
    Jump { idx: usize },
}

enum DocsPaneCommand {
    Focus { idx: usize },
    Drop { idx: usize },
    Clear,
}

enum PaneCommand {
    Input(InputPaneCommand),
    Results(ResultPaneCommand),
    Docs(DocsPaneCommand),
}

enum ParsedCommand {
    Global(GlobalCommand),
    Pane(PaneCommand),
}
```

補完・ヘルプ用:

```rust
struct CommandSpec {
    name: &'static str,
    aliases: &'static [&'static str],
    usage: &'static str,
    summary: &'static str,
    scope: CommandScope,
}

enum CommandScope {
    Global,
    Pane(PaneKind),
}
```

補完時は `CommandSpec` をマージして利用する。

## 11. 補完候補モデル

```rust
enum CompletionKind {
    Local,
    Function,
    Module,
    Type,
    Keyword,
    Command,
}

struct CompletionItem {
    label: String,
    kind: CompletionKind,
    signature: Option<String>,
    type_summary: Option<String>,
    detail: Option<String>,
}
```

表示ルール:

- 関数は `signature`
- 変数は `type_summary`
- 型は型ヘッダ
- コマンドは usage と summary を表示

## 12. エラーハンドリング

### 12.1 入力エラー

- コマンドとして解釈不能な場合は結果ペインにエラー表示
- 補完不能は単に候補なしとする

### 12.2 評価エラー

- 実行結果ペインへ明示的に表示
- 入力内容と関連づける

### 12.3 ドキュメント解決失敗

- 対象が存在しない場合は結果ペインへエラー表示
- ドキュメントキューには追加しない

## 13. 初期実装の必須範囲

初版では以下を必須とする。

画面:

- 実行結果ペイン
- ドキュメントビューペイン
- 補完ペイン
- 入力ペイン
- ステータスバー

入力:

- 複数行入力
- `:` によるコマンドモード切替
- 左右カーソル移動
- 上下による候補選択
- `Ctrl+C` による終了

コマンド:

- `:q`
- `:help`
- `:doc <symbol>`
- `:sig <symbol>`
- `:type <expr>`
- `:v idx`
- `:j idx`
- `:doc-focus idx`
- `:doc-drop idx`
- `:doc-clear`

補完:

- コマンド補完
- シンボル補完
- 型またはシグネチャ表示

## 14. 将来拡張

- `:ast`
- `:hir`
- `:bytecode`
- `:expand`
- pin 機能
- エラー専用ジャンプ

## 15. 仕様上の要点

本 REPL の重要点は以下である。

1. CLI 風の履歴表示を保つこと
2. 入力ペインは複数行で下部固定であること
3. 補完は入力の直上に出ること
4. 補完候補には型またはシグネチャを出すこと
5. コマンドはグローバルとペイン専用に分かれること
6. ドキュメントビューはキュー方式であること
7. `type` は式用、`sig` は定義用として意味を分離すること

## 16. 推奨実装順

1. 入力ペイン + 結果ペイン
2. コマンドモード
3. ドキュメントビュー
4. 補完ペイン
5. フォーカス管理
6. 型・シグネチャ付き補完
7. ドキュメントキュー操作
