- [x] **中・修正済み｜停止済み process の保持** — 旧実装は Stopped 本体を process 表へ残していた。2026-10-10 の改修では停止要求と完了を分け、未完了実行がなくなった時点で本体を削除する。旧 PID は不変 identity だけを共有し、本体・state・mailbox・継続を保持しない。
  - 修正: `request_process_stop` / `finish_process_execution` / `reclaim_stopped_process` が受付、完了、回収を担う。copy-on-write の停止識別表には Weak だけを保存し、spawn / 停止完了 / chunk の管理境界で参照のない entry を除く。旧 PID と lease を保持しても回収後の新規要求は同じ `ProcessStopped` となり、UnknownPid へ変えない。Workers・supervisor の所属解除と補充は停止完了後に一度だけ行う。
  - 受入: active VM の本体と不要な queue / waiting / reply / deadline / task / owner 参照が減り、旧 PID だけでは state を保持しない。停止前 checkpoint の保持は rollback 用と区別し、破棄後の物理解放まで確認する。全 handle を捨てた後の管理境界で死んだ停止識別 entry が減り、履歴に比例して増えない。
  - 回帰と未検証範囲: `crates/eldr/src/vm/process_identity_tests.rs` の PID copy / lease・checkpoint 破棄・identity / 型・別 VM・rollback ID 非再利用と、`process_stop_tests.rs` の本体・管理参照回収が対応する。32回の spawn / stopで本体・実行・task・不要futureは0件、copy / lease保持中の停止識別は1件、全handle破棄後の管理境界では0件になった。Weakでstateと待機frameのcapture、checkpoint破棄後のstateの物理解放を確認した。公開 fixture `process_reply_later_timeout_stop_reclaims.srt` は callback 待機中の所属保持、旧 lease 拒否、完了後の補充を固定する。最終結果は[実行時の継続調査書](runtime_audit_followup_20261010.md#2026-10-10-停止回収修正の最終検証)に記録した。大規模 benchmark、RSS 一般、Lazy 初期化・一般の restart / shutdown driver はこの修正だけで完了としない。

- [x] **高・修正済み｜GenServer の再入停止後に状態が復活** — 旧実装では、内側 Stop の後に外側 Reply の store が Stopped 本体へ state を戻し、同 PID の次の value call まで成功した。2026-10-10 の改修では、停止受付と実行段階を分離し、開始済み外側の保存・返答を許しながら受付を閉じたまま保つ。
  - 旧再現: MyWorker::stop_now(Process::self()) を SafeBind し、内側で StopReply::Normal(state)、外側で Reply(stopped + 1, state + 1) を返す。MyWorker::init(5) の PID に stop_then_reply と value を順に呼ぶと双方 Ok(6) だった。process_store が停止状態を検証せず state を再保存したことが最初の契約違反である。
  - 修正: canonical `__process_execute` が宛先検証・受付確認・state snapshot 取得・実行登録を原子的に行う。Handling で snapshot を一度読み、handler 正常復帰後の `__process_postprocess` で Postprocessing に移って store / Stop / ReplyLater を許す。callback は同じ record の Callback 段階とし、保存権限を持たない。境界外 state 読取、別個体・Handling / Callback・保存済み実行からの store は RuntimeError とする。
  - 受入: 再入 Stop 後の外側 Reply / Next / ReplyLater は本来の結果で一度だけ完了し、新しい子 call と後続の同 PID の要求は ProcessStopped になる。停止中の開始済み wrapper の state 保存を一律禁止しない。Normal / Error Stop の4応答、最初の終了理由、callback の future / timer 待機、timeout 結果の一度だけの配送を維持する。
