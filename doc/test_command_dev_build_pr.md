# 開発ビルドの test コマンド改修案

作成日: 2026-10-04

状態: 改修PRの仕様・計画。製品コードと実行可能なテストは未変更。

## 目的

開発ビルドの `surtr test` は、引数で実行対象を明示する。単体指定を `lib/tests` 基準のテスト名として扱う旧経路を削除し、指定されたファイルパスをそのまま読む。

開発用 `--all` は標準テストの入口を列挙し、単体実行と同じ処理で1スクリプトずつコンパイル・実行する。プロジェクトモードのテスト戦略は別課題として1から設計する。

## 対象と対象外

- 対象はRuneの開発ビルドにおける引数解析、対象選択、テストファイル読み込み、関連するテストと文書。
- level2。言語の構文・型規則・評価規則を変えず、CLI の対象選択契約を置き換える。
- リリースビルドのプロジェクトモードは実装しない。現時点の知見は [リリースビルド改修メモ](./test_command_release_build_memo.md) に分ける。
- 失敗位置の推測は別ブランチで対応済み。本PRでは調査・修正を重ねない。統合時にその変更を保持する。
- 並列コンパイル、複数スクリプトの一括コンパイル、共通プロジェクト環境のキャッシュ設計は対象外。

## 現行挙動と問題

`crates/rune/src/commands/test.rs` は単体引数に次の処理を行う。

1. 前後の空白を除去し、バックスラッシュをスラッシュに変換する。
2. 先頭の `./` と `lib/tests/` を除去する。
3. 末尾が `.srt` でなければ `.srt` を補完する。
4. `lib/tests/` を付けて読み込む。
5. 親ディレクトリ成分、絶対パス、実体が `lib/tests` 外になるsymlinkを拒否する。

このため `surtr test tes.srt` はCWDの `lib/tests/tes.srt` を読む。引数から期待されるCWDの `tes.srt` を読まず、プロジェクトルートの探索も行わない。

現行 `--all` は `lib/tests/**/*.srt` を再帰的に探索し、schema、spec module fixtures、特定の補助ファイル名を除外する。実行自体は既にスクリプトごとの順次実行であり、全スクリプトを1つのコンパイル単位にまとめてはいない。

## 変更後の契約

### 単体ファイル指定

```text
surtr test [--quiet|-q] <file-path>
```

- 相対パスは起動時のCWDを基準に読む。
- 引数の文字列をファイルパスとして扱い、前後の空白除去、区切り文字変換、拡張子補完、`lib/tests` への付け替えを行わない。
- `./` と `..` は通常の相対パスとして扱う。`lib/tests` 内限定の字句検査・実体パス検査を削除する。
- 指定ファイルを読めなければエラーにする。同名の標準テスト、別の拡張子、別のディレクトリを探さない。
- 拡張子省略は名前補完の指示ではない。`surtr test tes` は `tes` そのものを読もうとする。
- includeは指定スクリプトの位置を基準に解決する既存契約を使う。CLIの引数解釈とincludeの解決を混ぜない。
- 対象なし、複数対象、ファイルと `--all` の併記、未知のオプション、オプションの重複は引き続きエラーにする。
- `--quiet` / `-q` の出力契約は維持する。

呼び出しと対象の対応は次のとおり。

| 呼び出し | 読み込む対象 |
|---|---|
| `surtr test tes.srt` | CWD の `tes.srt` |
| `surtr test ./tests/tes.srt` | CWD の `tests/tes.srt` |
| `surtr test ../tests/tes.srt` | CWD の親から見た `tests/tes.srt` |
| `surtr test lib/tests/string.srt` | 明示した `lib/tests/string.srt` |
| `surtr test string` | CWD の `string`。`lib/tests/string.srt` へ切り替えない |

絶対パスの受入契約は本案の確定事項に含めない。実装前に扱いを確定し、旧仕様の `lib/tests` 内限定規則をそのまま根拠にしない。

### 開発用 all

```text
surtr test [--quiet|-q] --all
```

以下を改修案とする。

- 対象はCWDの `lib/tests/*.srt`。直下の通常ファイルとして読めるテストスクリプトを列挙する。
- サブディレクトリを再帰探索しない。
- 辞書順に、各スクリプトの依存収集、コンパイル、VM実行を行う。
- 各スクリプトには独立したVMを用意し、結果を集計する。
- 対象ファイルは単体実行と同じ読み込み・コンパイル・実行処理に渡す。ファイルパスを省略名に戻す処理も削除する。
- `schema/**` や `spec/modules/**`、`prelude.srt`、`spec_defs.srt` を名前で除外する規則を削除する。
- include専用ファイルはサブディレクトリに配置する。現在直下にある `spec_defs.srt` は、例えば `lib/tests/support/spec_defs.srt` へ移し、参照元のincludeを更新する。
- 不要な互換placeholderが残っている場合は削除する。名前による除外で温存しない。
- ディレクトリ読み込み・ファイル読み込み・コンパイル・実行の失敗を成功に置き換えない。現行同様、個別の失敗を集計して最終終了コードを失敗にする。

直下に絞る目的は、テストの入口と include 専用依存を配置で分けること。再帰探索の有無と並列コンパイル対応の有無は独立した選択である。

### ビルド種別の境界

開発用 `--all` の対象選択はRuneで分岐する。開発ビルドの判定には `cfg(debug_assertions)` を使う案とし、リリース用プロジェクトモードを開発用の列挙処理へフォールバックさせない。

プロジェクトモードが未実装のリリースビルドでは、`--all` に対して未対応であることを示すエラーを返す案とする。この境界以外のリリース用テスト戦略は本PRで実装しない。

## 依存とキャッシュ

異なるスクリプトが同じ依存をincludeしても、コンパイル単位が別なので、それだけで重複にはならない。同じコンパイル単位内の重複includeや定義衝突について、all専用の許可規則を追加しない。

開発ビルドでは既存のテスト用標準環境のスナップショットとキャッシュを利用する。今回の対象選択変更を、ユーザプロジェクトの共通環境キャッシュ設計と結び付けない。

現行の依存コンパイルキャッシュは入口スクリプトにもキーが依存するため、異なるテスト間で共通依存を共有する保証はない。この問題の設計はリリース用メモに残す。

## 今回変更しない未確定事項

次の挙動は調査で判明しているが、本PRの対象選択修正と合わせて無条件に変更しない。

- CWD の `lib` に配置された追加モジュールの自動収集。include と衝突しうるため、プロジェクトモードの設計で再整理する。
- テスト0件・all対象0件の終了コード。現行は成功扱い。0件をエラーにするかは別途契約を決める。
- キャッシュの読み込み・ロック・保存失敗を隠す処理、CWD取得失敗時の `.` への置換、rename失敗時のcopyへの切り替え。

パスに `lib/tests/spec/` が含まれる場合だけ0件の通知を省略する特例は、対象選択整理に合わせて削除する案とする。0件の終了コード自体とは分けて扱う。

## 実装計画

1. 絶対パス、直下のみのall対象選択、ビルド判定と未対応releaseの境界について本案を確定する。
2. 正本文書のCLI契約を更新し、新しい対象選択の成功・拒否境界をテストに固定する。
3. 単体引数を実ファイルパスとして扱う経路に置き換え、旧selectorの変換・限定検査を削除する。
4. allの列挙を直下に限定し、補助ファイルの配置とincludeを更新する。名前による除外とパスによる0件通知の特例を削除する。
5. 既存の標準環境・キャッシュ・単体実行処理を使って順次実行する。検証後にPRの説明を最終差分へ合わせる。

## 変更対象

- `crates/rune/src/commands/test.rs`: 引数解析、パス読み込み、all列挙、ビルド種別の境界。
- `crates/rune/src/error.rs`: usageの `<lib-relative-name|--all>` を新しいCLI契約に合わせる。
- `tests/integration/test_command.rs` とRune内単体テスト: 旧selector前提を置き換える。
- `lib/tests/spec_defs.srt` と参照元: 補助ファイルの移動・include更新。
- `crates/rune/README.md`、`docs/dev/Rune_cli_spec.md`、`docs/dev/テスト方針.md`、`tests/README.md`、`docs/dev/FS_Shell_spec.md`: 対象選択・呼び出し例を同期する。
- 開発スキル等に残る省略名の実行例は実装時に整理対象を確認し、更新漏れを残さない。

## 受入条件

- CWD の `tes.srt` と `lib/tests/tes.srt` を別内容で用意し、`test tes.srt` が前者だけを実行する。
- 明示した `lib/tests/tes.srt` は後者を実行する。
- 指定ファイルが存在せず、同名ファイルが `lib/tests` にあっても、代わりに実行しない。
- 拡張子の自動補完、前後空白の除去、バックスラッシュの独自変換を行わない。
- 親ディレクトリの相対パスと、`lib/tests` 外のファイルへのsymlinkを、通常のファイル指定として扱う。
- 引数の不足・競合・重複・未知オプションをエラーにする。
- allは直下のスクリプトを辞書順に実行し、ネストした補助ファイルを入口として実行しない。
- 2つのスクリプトが同じ補助ファイルをincludeしても、それぞれ単体・allの両方で実行できる。
- 同一コンパイル単位内の重複include拒否を、allだけ緩めない。
- quietの成功時抑制・失敗時出力と失敗終了コードを維持する。
- release側に開発用allへのフォールバックを残さない。

## 検証計画と現時点の結果

実装時はRuneの対象選択単体テストとCLI境界のテストでTDDを行う。

```sh
rtk cargo nextest run --profile cold -p rune --test integration test_command
rtk cargo build -p rune
rtk proxy ./target/debug/surtr test --quiet --all
rtk cargo nextest run --profile ci --workspace
cargo fmt --all -- --check
git diff --check
```

release側の境界を追加する場合は、releaseビルドの `--all` が未対応エラーになることも確認する。プロジェクトモードのテスト成功としては扱わない。

本書作成時は追加調査、製品コード変更、ビルド、テスト実行を行っていない。直下のみのall等は今回の改修案であり、未実装である。
