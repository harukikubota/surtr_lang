# Scar 型関係チェックの性能要件

## 背景

構造化診断のため、型関係チェックは失敗時に途中の型変数束縛を戻す。一方、候補探索用のチェックポイントは `TypeEnv` や Trait 情報なども複製するため、標準定義に多いジェネリックな関数本体で毎回使うと型検査時間が増える。

## 要件

- 型関係チェックが成功した場合は、推論で得た束縛を保持する。
- 型関係チェックが失敗した場合は、その関係チェックが変更した型変数束縛、境界、保留中の Trait obligation を元に戻す。
- rigid な型変数だけを含む比較では、変更可能な推論状態のチェックポイントを作らない。
- 候補探索専用の状態全体を、通常の型関係チェックで複製しない。
- 診断の reason、source fact、expected/actual の向きは変更しない。

## 検証

- 部分的な束縛後に失敗する関係チェックが状態を戻し、後続の比較で別の型を選べることを単体テストで固定する。
- rigid な型関係チェックと失敗する通常の型関係チェックが、候補探索用チェックポイントを作らないことを単体テストで固定する。
- `cargo test -p scar` で Scar の契約を確認する。
- `rtk` を介さず、同一環境の `cargo test --all` と Scar の同一 test suite / bucket を修正前後で比較する。
