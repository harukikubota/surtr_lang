# 文字列リテラルの実装契約

通常文字列の入力規則は[言語リファレンス](../site/language-reference.md#文字列)、利用例は[文字列の入力と表示](../site/strings.md)を正本とする。本書はSpire内の情報の受け渡し、診断位置、静的文字列とraw文字列の境界、Sindrの引用表示を定める。

## 通常文字列の解析

`"..."` と `'...'` は同じエスケープ規則を使う。復号対象は `\\`、`\"`、`\'`、`\n`、`\t`、`\u{HEX}`、`\#{` であり、それ以外は拒否する。`\#` は直後が `{` の場合だけ有効である。Unicodeエスケープは16進数1〜6桁のUnicodeスカラー値とし、空白、符号、`_`、サロゲート、U+10FFFF超過を拒否する。非文字はスカラー値として受理し、Unicode正規化は行わない。

Spireは元ソース上の文字列区間、補間式区間、位置情報を保持し、文字列区間を一度だけ復号する。引用符の終端と補間の開始は復号前の元ソースで決める。
文字列payloadは、補間を含まない復号済み値の `Plain` と、復号済みtext・元ソースの補間式・spanを保持する `Interpolated` に分ける。
通常式とregex sugarは両方を扱い、静的文字列consumerは `Plain` だけを受理する。
`Interpolated` の式ソースを字面へ変換する経路や、静的consumer専用の復号規則は設けない。

- 元ソースを左から読み、エスケープが消費した範囲を補間判定へ戻さない。
- `\u{...}` 内の波括弧を補間の波括弧として数えない。
- 復号した `#`、`{`、`}`、引用符、バックスラッシュを再び構文として解釈しない。
- 補間式のソースには、外側の文字列の復号を適用しない。式内の文字列は自身の引用符と規則で解析する。
- 単一・二重引用符、regex sugar、静的文字列で復号規則を共有し、各consumerに複製しない。
- 復号済みの文字列を元ソースとして再解析・再復号しない。補間抑止のためのダミー文字や特殊なUnicode文字も使わない。

補間式の既存の評価順序とShow契約は維持する。

### 補間開始の境界

以下は引用符内の元ソースを表す。`name` の値は通常の式として補間する。

| 元ソース | 結果 |
|---|---|
| `#{name}` | `name` を補間 |
| `\#{name}` | 文字としての `#{name}` |
| `\\#{name}` | バックスラッシュ1文字の後で補間 |
| `\\\#{name}` | バックスラッシュ1文字と、文字としての `#{name}` |
| `\u{23}{name}` | 文字としての `#{name}` |
| `#\u{7b}name}` | 文字としての `#{name}` |
| `\u{5c}#{name}` | バックスラッシュ1文字の後で補間 |

この消費規則で、元ソースのバックスラッシュの偶奇が決まる。復号後のバックスラッシュの数から推定し直さない。

## 診断と未完入力

不正なエスケープはSpireの `LiteralSyntax` エラーにする。未知エスケープ、必須の波括弧欠落、数字なし、無効な桁、桁数超過、スカラー値範囲外を原因別に示す。文字列値を生成せず、unknown tokenや代替文字への置換で原因を隠さない。

診断spanは元ソース上の該当エスケープを指す。補間式の診断も元ソース位置を保持し、前方の `\u{...}` の復号によって位置がずれないようにする。復号後の文字数を元ソースのoffsetとして使わない。診断の一般契約は[diagnostics](./diagnostics.md)に従う。

EOFで追加入力により成立できる場合は `IncompleteInput` とする。

| EOFまでの入力状態 | 判定 |
|---|---|
| 開いた文字列、末尾の `\`、`\#`、`\u`、`\u{`、有効な桁までの `\u{1b` | 未完入力 |
| `\u{d800` | 桁を追加して有効値にできるため未完入力 |
| `\u{110000` | 6桁ですでに上限超過のため解析エラー |
| 無効な桁、7桁以上、閉じる引用符により不正が確定した入力 | 解析エラー |

範囲とサロゲートの判定は `}` で値が確定した時点で行う。ただし、許容桁数内で数字を追加しても有効なスカラー値にできない接頭辞はその時点で拒否する。ファイル入力が未完のまま終われば解析失敗となる。

上記のEOF判定は、parserに渡したソースがそこで終わる場合の契約である。Unicodeエスケープ内の空白・改行は無効な桁として拒否する。REPLが物理行を連結して改行を挿入した場合、その改行も解析対象となるため、escape途中の入力を次の行で完成できることは保証しない。REPLの継続待機は[Xldr](./Xldr_spec.md#43-複数行入力)の入力契約に従う。

tolerant parserとLSPも同じ復号・拒否規則と診断原因を使う。編集中の回復で診断を保持して解析を続けても、不正なエスケープを有効な文字列値として扱わない。strict parserとの間に未知エスケープを保存する別経路を設けない。

## 使用箇所ごとの契約

| 使用箇所 | 通常エスケープの復号・拒否 | 補間 |
|---|---|---|
| 通常の文字列式 | 適用 | 元ソースのエスケープされていない `#{...}` を評価 |
| `re"..."` / `re'...'` | 適用 | 通常式と同じ |
| Stringパターン、includeパス、文字列の宣言引数 | 適用 | `Plain` だけを受理し、`Interpolated` は拒否 |
| raw triple-quoted文字列式 | 適用しない | 既存の補間と `\#{` による抑止を維持 |
| `@doc` 本文 | 適用しない | 禁止 |

静的文字列も元ソースの `#{...}` を補間開始として認識するため、直接書いた補間は `Interpolated` として拒否する。字面は `\#{` と書く。
`"\#{name}"`、`"\u{23}{name}"`、`"#\u{7b}name}"` は `Plain` の `#{name}` となり受理する。
`"\\#{name}"` と `"\u{5c}#{name}"` は元ソースに補間開始が残るため `Interpolated` として拒否する。
静的consumerは補間式を評価せず、式ソースの復号や文字列への再構成も行わない。`Interpolated` を渡した場合は `LiteralSyntax` エラーにする。通常文字列の診断は使用箇所によって緩和しない。

Regex sugarは通常文字列を `Regex::compile` に渡す。`re"\\d"` は正規表現の `\d` を渡すが、`re"\d"` はSpireで拒否する。regex専用のエスケープ復号や未知エスケープの救済を設けない。復号後の正規表現の検証は `Regex::compile` が担う。

raw本文と `@doc` は既存のdedent規則を維持する。たとえばraw本文の `\u{1b}` は6文字のままであり、通常文字列の復号済み内容として処理しない。

未知エスケープと静的使用箇所の補間の拒否は意図的な非互換変更である。旧静的文字列の字面 `#{...}` は `\#{...}` に書き換える。従来の `"\q"` は `"\\q"`、regexの `re"\d"` は `re"\\d"` に書き換える。互換モード、警告だけの旧経路、内部表現の違いを隠すフォールバックを残さない。旧入力をテストに残す場合は拒否条件と診断を検証する。

## 共通の引用表示

Sindrの `quote_surtr_string_literal` は二重引用符で囲み、以下を適用する。

| 内容 | 引用符内の表記 |
|---|---|
| バックスラッシュ／二重引用符 | `\\`／`\"` |
| LF／TAB | `\n`／`\t` |
| その他のC0、DEL、C1 | 小文字16進数・不要な先頭ゼロなしの `\u{...}` |
| 連続する文字としての `#{` | `\#{` |
| その他 | そのまま |

対象範囲はU+0000〜U+001F、U+007F〜U+009Fである。引用表示を通常式として解析・評価すると元のStringと等しくなることを、任意の有効なUTF-8文字列について保証する。文字の削除やUnicode正規化は行わない。

EldrのString `inspect`、List・Tuple・Result・構造体の入れ子、HashMapキーと引用される値、Xldrの束縛・単独評価・履歴値表示はこの共通処理を使う。ESCと `a` を持つStringは `"\u{1b}a"` と表示し、色なしCLI出力の引用部分に値由来の生のESCを残さない。CLIの色付け用ANSI列は別に維持する。表示層で端末別の回避策を追加しない。

往復保証はString単体に限る。private field省略やError表示などを含む `inspect` 全体のソース化は保証しない。`to_string(String)` と `print(String)` は生文字列を扱う既存の契約を保つ。`eprint` はErrorを診断表示し、それ以外の値は `inspect` 経由で出力するため、`eprint(String)` には共通引用処理を適用する。HashMapキーなどの既存の引用箇所には共通規則を適用する。

VM命令、文字列の実データ、型規則は変更しない。Unicode双方向制御文字・ゼロ幅文字・行区切り文字の一般的な可視化、Errorの非引用メッセージや診断全体の端末制御文字対策は本契約の対象外である。

## 検証する境界

入力は両引用符、U+0000・U+001B・U+007F・U+0080・U+D7FF・U+E000・U+10FFFF、大文字数字と先頭ゼロ、サロゲートと上限超過、未知エスケープと書式不正を検証する。補間は上記の元ソース境界、補間式内の文字列、エスケープ前後の元ソースspanを検証する。静的文字列・regex・raw・`@doc`・tolerant parserも使用箇所の契約に照らして確認する。

表示の往復テストは再評価したStringと元のStringの値を比較する。表示スナップショットだけで代用せず、全C0・DEL・C1、引用符、バックスラッシュ、文字としての `\u{...}` と `#{`、通常のUnicode文字を含める。入れ子、HashMapキー、REPLの束縛・式・履歴、CLIの出力バイト列と色付き出力、元データのcodepointsと連結結果、明示的な生出力も検証する。
